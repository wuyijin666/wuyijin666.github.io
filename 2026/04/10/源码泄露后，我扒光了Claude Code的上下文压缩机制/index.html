源码泄露后，我扒光了Claude Code的上下文压缩机制

文章摘要：一个真正在实际生产环境中承载数百万次对话的LLM应用，它到底是如何处理上下文窗口这个最根本的限制的？这是一份难得的工程参考

一、 背景

模型的上下文窗口是整个系统中最宝贵的资源。以Claude Sonnet 4.6为例，其上下文窗口约200k tokens,但一次完整开发流程（代码阅读 、 多轮对话、错误调试）很容易超出这个限制。
如果不加管理，token上限，API会返回413 prompt_too_long , 对话被迫中断。cc为此设计了一套多层次、优先级明确的压缩体系。

  • 理解这套体系的关键。先理解一个核心参数 ： 有效上下文窗口（Effective Context Window）

“有效窗口” = 模型原始上下文窗口 - 20,000（为摘要输出预留）。这20,000 token的预留基于生产数据的p99.99统计值（压缩摘要输出的最大值为17,387tokens）

二、cc的四种策略全景

  • 四种策略按触发时机和代价排序

三、浅析上下文压缩方案

3.1 Auto压缩：主动防线

3.1.1 触发阈值

token数超过以下阈值将触发Auto压缩:
Auto触发阈值 = 有效上下文窗口 - 13，000（AUTOCOMPACT_BUFFER_TOKENS）
预留13.000是为了确保压缩任务本身（发送历史+接收摘要）有足够空间

  • Manual压缩的buffer只有3，000，原因在于manual时用户已经知道问题，无需额外安全余量

3.2 Reactive压缩：被动防线

Reactive压缩是Auto的反面 – 不主动判断token数，而是让api返回413错误才行动

扣押（withhold）机制使得用户完全感知不到这次413–用户体感是一次透明的压缩后重试
防止死循环：hasAttemptedReactiveCompact 标志确保Reactive每次query只尝试一次

3.3 Snip：零成本的历史消息裁剪

Snip是最‘轻量’的压缩策略:不调用LLM，直接删除历史记录

四、策略优先级总结

  • 先用廉价，再用昂贵
    1. 最优：无LLM策略（Snip/Microcompact/Session Memory）,零延迟，零额外API成本
    2. 次优：Auto主动压缩，需一次api调用但完全透明
    3. 最后：Reactive压缩，在主动防线失败时兜底

压缩完成时，历史消息被替换为一条特殊的摘要消息，前面加上边界标记：

摘要以一条包装消息的形式注入，开头声明‘this session is being continued from a previous conversation’,让模型知道上下文被压缩过，避免它因为‘记忆缺失’产生疑惑

五、总结

六种相互协同的策略、精密的触发阈值设计、专门对抗模型‘工具调用冲动’的Prompt工程、以及将LLM摘要调用频率降至最低的Session Memory机制。
我们从4个问题出发：何时压缩（触发策略）、如何压缩（LLM Prompt设计）、压缩什么（信息保留优先级）、如何验证压缩没丢失关键上下文。
读完本文，你将理解为什么一个‘把对话缩短’的功能，在工程上实现会如此复杂–以及这些设计决策背后真正的工程代价。

六、六旬老人也能看懂的总结：

您想象一下，Claude Code 就像是一个记性有限的小助手，它脑子里能装的东西有个上限——大概能装 200 页纸的内容。

  • 问题出在哪儿呢？
    您跟它聊天、让它改代码、调试程序，说着说着，它脑子就装不下了。就像您去菜市场买菜，拎的袋子满了，再买就拎不动了，得把一些不重要的东西先放一放。

  • 它是怎么”省地方”的？
    这篇文章讲了 6 种”省地方”的办法，我给您说说：

  1. 直接扔掉旧话（Snip）—— 把最早说的几句话删掉，不费脑子，立马腾地方

  2. 清理过期工具结果（Microcompact）—— 比如它之前帮您查过什么文件，查完了就不用老记着，删掉

  3. 主动总结（Auto）—— 快满的时候，它自己把之前的对话总结成一小段，就像把厚书缩成薄薄几页

  4. 被动总结（Reactive）—— 真装不下了，系统报错，它赶紧总结一遍再重试

  5. 手动总结（Manual）—— 您主动说”咱把之前的总结一下”

  6. 用现成的笔记（Session Memory）—— 如果之前已经记过笔记了，直接拿出来用，最省事儿

最妙的地方
这系统有个特别聪明的设计：先试不花钱的办法，实在不行再花钱。就像您过日子，能省则省，真到没办法了再掏腰包。

而且它总结的时候，会先把您的所有原话都保留下来，怕忘了您最初想干啥——这就像您出门前写的购物清单，怕逛着逛着忘了要买啥。

  • 简单说：这就是一个 AI 助手为了不”脑子爆掉”，想出来的各种省地方的招儿，跟咱们过日子收拾屋子一个道理——该扔的扔，该总结的总结，实在不行再重新整理！🍮
